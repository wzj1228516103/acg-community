## 1. 产品概述

### 1.1 产品愿景

漫化是一个面向二次元文化爱好者的综合社区平台，核心价值主张为："让二次元文化更加精彩，让每个人都能找到属于自己的角色"。

平台围绕三条核心业务线展开：
- **电商交易**：二次元周边商品（Cosplay服饰、道具、假发、手办、文创周边）的在线购买
- **专业服务**：认证化妆师提供的Cosplay妆容、特效妆、假发造型等线下/线上服务预约
- **社交互动**：用户间的即时聊天沟通，连接消费者与服务提供者

### 1.2 平台数据指标（愿景）

| 指标 | 目标值 |
|------|--------|
| 认证化妆师 | 1000+ |
| 精选商品 | 5000+ |
| 活跃用户 | 10W+ |
| 服务保障 | 7×24小时 |

### 1.3 设计理念

- **品牌色系**：粉紫渐变（`from-pink-500 via-purple-500 to-indigo-500`），传递二次元梦幻感与年轻活力
- **品牌标识**：心形图标 + "漫化" 文字标识
- **设计语言**：圆角卡片、半透明毛玻璃效果、渐变色彩、Lucide 图标库
- **响应式**：移动端优先，支持桌面端自适应

## 5. 用户账户模块

### 5.1 注册

- **入口**：顶部导航栏"注册"按钮、登录页底部链接
- **表单字段**：
  - 手机号（必填，11位中国手机号，格式校验）
  - 密码（必填，6-20位）
  - 确认密码（必填，需与密码一致）
- **流程**：
  1. 填写表单 → 提交注册
  2. 系统创建用户记录（Supabase Auth）
  3. 注册成功自动跳转至首页，状态变为已登录
  4. 系统自动生成默认昵称（格式：`漫小团_XXXX`）

### 5.2 登录

- **入口**：顶部导航栏"登录"按钮
- **表单字段**：
  - 手机号 / 邮箱（必填）
  - 密码（必填）
- **流程**：
  1. 填写凭据 → 提交登录
  2. 通过 Supabase Auth 验证 → 获取 Session
  3. 用户状态写入 localStorage（`currentUser` key）
  4. 登录成功后跳转至首页

### 5.3 退出登录

- **入口**：用户下拉菜单底部"退出登录"
- **流程**：
  1. 清除 localStorage 中的 `currentUser`
  2. 清除全局 Auth Context 中的 user 状态
  3. 跳转至首页

### 5.4 个人中心（`/profile`）

- **展示信息**：
  - 头像（默认与上传）
  - 昵称（可编辑）
  - 手机号（脱敏显示）
  - 角色标签
- **快捷入口**：
  - 我的订单 → `/orders`
  - 化妆订单 → `/makeup-orders`
  - 我的收藏 → `/favorites`
  - 个人设置 → `/profile-settings`

### 5.5 个人设置（`/profile-settings`）

- 修改昵称
- 修改头像
- 修改密码 → `/change-password`
- 绑定/更换手机号

### 5.6 会话持久化

- 登录状态通过 `localStorage` 中的 `currentUser` JSON 对象持久化
- 页面刷新后自动从 localStorage 恢复会话
- Auth Context（React Context）作为全局状态管理用户信息

- **交互规则**：
  - 数量修改：步进器（-/+），最小 1，最大为库存量，超出库存时 Toast 提示"商品库存不足"
  - 删除商品：从购物车移除，Toast 提示"商品已从购物车移除"
  - 商品数量更新：同商品多次加入购物车时数量递增（而非重复条目）
  - 即时反馈：加入购物车时 Toast 提示"商品已添加到购物车"
- **去结算**：携带选中商品跳转 `/checkout`

### 7.5 订单结算页（`/checkout`）

- **订单确认信息**：商品清单、数量、单价
- **金额汇总**：合计金额
- **提交订单**：创建订单记录，清空购物车，跳转支付

### 7.6 订单管理

## 9. 即时聊天模块

### 9.1 技术架构

- **实时通信**：Supabase Realtime（基于 WebSocket / Phoenix Channels）
- **协议版本**：`realtime-js` v2.15.5
- **消息编码**：JSON + Binary format（自定义协议）
- **消息存储**：Supabase 数据库 `messages` 表 + `chat_rooms` 表

### 9.2 会话列表（`/chat`）

- **列表项结构**：
  - 会话头像（对方用户头像）
  - 会话名称
  - 最后一条消息摘要（文字）
  - 最后消息时间（刚刚 / 分钟前 / 日期）
- **排序**：按 `updated_at` 倒序（最近活跃优先）
- **数据查询**：获取当前用户参与的所有聊天室（`participants_json` 包含当前用户 ID）

### 9.3 聊天窗口

- **消息气泡样式**：
  - 自己发送：右对齐，主题色背景
  - 对方发送：左对齐，浅灰色背景
- **消息类型**：
  - 文本消息（`message_type: "text"`）
  - 图片消息（扩展）
  - 订单卡片消息（扩展）
- **加载顺序**：按创建时间正序排列（最早在上）
- **消息关联**：每条消息包含发送者 profile 信息（头像、昵称）

### 9.4 创建聊天室

- **触发方式**：从商品详情页"联系商家"、从化妆师详情页"联系化妆师"等
- **数据结构**：
  ```json
  {
    "id": "uuid",
    "name": "会话名称",
    "participants_json": "[\"user_id_1\", \"user_id_2\"]",
    "created_at": "ISO timestamp",
    "updated_at": "ISO timestamp"
  }
  ```
- **去重逻辑**：若两用户间已存在聊天室，直接复用而非新建

### 9.5 发送消息

- **消息数据结构**：
  ```json
  {
    "id": "uuid",
    "room_id": "聊天室ID",
    "sender_id": "发送者ID",
    "content": "消息内容",
    "message_type": "text",
    "created_at": "ISO timestamp"
  }
  ```
- **发送后自动更新**：
  - 聊天室的 `updated_at` 时间戳
  - 返回关联的发送者 profile 信息

## 13. 核心业务流程

`
用户访问注册页面  填写手机号和密码  提交注册  Supabase Auth 创建账户
 自动生成默认昵称  写入 localStorage  首次自动登录  跳转首页
`

### 13.2 购物与订单流程

`
浏览商城  查看商品详情  加入购物车（localStorage 存储）
 查看购物车（可修改数量/删除商品） 去结算  确认订单信息
 提交订单（创建 orders + order_items 记录） 跳转支付成功页
 订单状态：pending  paid  shipped  completed
`

### 13.3 化妆师预约流程

`
浏览化妆师服务广场  查看服务详情  点击预约  填写预约信息
 提交预约（创建 makeup_bookings，status=pending） 预约成功页
 化妆师确认（status=confirmed） 服务完成（status=completed） 用户评价
`

### 13.4 角色认证流程

`
普通用户  填写化妆师/商家认证资料  提交申请（status=pending）
 管理员审核
    通过（status=approved） 自动更新用户角色（makeup_artist/merchant）
    驳回（status=rejected） 通知用户驳回理由
`

### 13.5 即时聊天流程

`
用户点击联系商家/化妆师  查询现有聊天室（participants_json 包含双方 ID）
 存在则复用 / 不存在则创建  进入聊天窗口  输入消息  发送
 保存到 messages 表  更新 chat_rooms.updated_at
 Supabase Realtime 推送对方  对方实时收到消息
`

### 14.3 统一错误处理

| HTTP 状态码 | 说明 | 处理策略 |
|-------------|------|----------|
| 200 | 请求成功 | 正常处理返回数据 |
| 201 | 创建成功 | 新建资源成功 |
| 400 | 请求参数错误 | 前端 Toast 提示错误信息 |
| 401 | 未认证/Token 过期 | 清除本地存储，跳转登录页 |

## 16. 非功能性需求

### 16.1 性能要求

| 指标 | 目标值 |
|------|--------|
| 首屏加载时间（FCP） | < 2.5s |
| 最大内容绘制（LCP） | < 3.5s |
| 交互响应时间（TTI） | < 4s |
| 路由切换响应 | < 200ms |
| 图片懒加载 | 视口外图片延迟请求 |
| 首页数据加载 | 并行请求化妆师服务和商品列表 |
| 聊天消息加载 | 按需加载，支持分页 |

### 16.2 浏览器兼容性

| 浏览器 | 最低版本 |
|--------|----------|
| Chrome | 90+ |
| Safari | 14+ |
| Firefox | 88+ |
| Edge | 90+ |
| 移动端浏览器 | iOS Safari 14+, Android Chrome 90+ |

### 16.3 安全性

- **认证**：使用 Supabase Auth，支持 JWT Token 管理
- **API 鉴权**：所有操作需携带有效 Session Token
- **密码安全**：密码由 Supabase Auth 托管加密，不明文传输
- **RBAC**：基于角色的前端路由守卫（角色不匹配时隐藏对应导航入口）
- **数据校验**：前端表单校验 + 后端数据库约束（如 `favorites` 表的唯一约束防止重复收藏）
- **敏感数据**：身份证号加密存储，手机号脱敏显示
- **会话管理**：localStorage 持久化，刷新页面自动恢复

### 16.4 可维护性

- **组件化**：React 函数组件 + Hooks，提取可复用 UI 组件
- **状态管理**：React Context（AuthContext、CartContext）管理全局状态
- **localStorage**：购物车和登录状态本地持久化，提升用户体验
- **Mock 数据**：支持前端离线开发模式（`!$` 判断 Supabase 连接可用性，不可用时返回 Mock 数据）
- **路由懒加载**：基于 React Router 的嵌套路由实现代码分割
- **Toast 通知**：统一的 Sonner 组件提供操作反馈
- **代码规范**：使用 Tailwind CSS 类名优先、保持一致的组件结构
